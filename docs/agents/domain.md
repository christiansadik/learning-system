# Domain Documentation

This project uses a single context.

Before exploring or changing the project:
- Read `GLOSSARY.md`.
- Read relevant decisions in `docs/adr/`, if present.

Use the glossary's terminology consistently.
Flag conflicts with existing decisions.

Keep the glossary limited to domain definitions.
Create ADRs only for consequential, hard-to-reverse trade-offs.
Missing ADR files do not block work.
